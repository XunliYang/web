# 社区导师培养机制设计文档

---

## 一、整体框架

### 1.1 设计目标

建立公司内部社区导师培养机制，通过专家带新人的方式：
- 帮助员工快速融入真实开源项目
- 提升团队开源贡献能力和规范意识
- 形成可复用的导师制流程与规范

### 1.2 适用人群

- 新入职员工（加入公司 ≤ 6个月）
- 现有开发人员（已有工作经验但开源参与经验不足）

### 1.3 核心流程

```
导师认证 → 导师池管理 → 学员筛选配对 → 周期培养 → 里程碑评审 → 结项
```

---

## 二、导师池管理

### 2.1 导师资格认证

**准入标准（技术能力 + 软技能）：**

| 维度 | 技术能力要求 | 软技能要求 |
|------|-------------|-----------|
| 基础 | 在目标开源项目有 ≥ 3 个 merged PR | 能清晰表达技术概念 |
| 进阶 | 熟悉项目核心模块，能独立完成中等难度任务 | 有过指导他人经验（非正式也可） |
| 高级 | 获得 Comitter/Maintainer 认可，参与项目决策 | 能进行 Code Review 并给出建设性反馈 |

**认证流程：**
1. 员工自荐或团队推荐
2. 提交申请材料（贡献记录、技术博客、指导案例）
3. 认证委员会评审（技术主管 + 资深导师代表）
4. 颁发导师认证（分初级/高级两级）

### 2.2 导师池维护

- **导师档案**：记录擅长领域、可指导人数、当前指导状态
- **动态调整**：每半年重新认证，连续两个周期无指导记录降级
- **退出机制**：主动退出或违反规范取消资格

### 2.3 导师激励

| 类型 | 内容 |
|------|------|
| 荣誉激励 | 颁发认证证书、公司内部表彰、年度优秀导师评选 |
| 物质激励 | 每季度指导津贴、绩效加分、晋升通道优先 |

---

## 三、学员管理与配对机制

### 3.1 学员筛选

由组织根据项目需求和人员情况统一筛选。

### 3.2 配对流程

```
组织筛选学员 → 根据技术栈/项目需求匹配导师 → 正式建立指导关系
```

### 3.3 配对原则

- 一位导师同时指导不超过 2 名学员
- 优先考虑技术栈匹配度和导师对目标项目的熟悉程度

---

## 四、周期培养机制

### 4.1 周期定义

- 培养周期：6个月

### 4.2 评审节点

| 时间点 | 评审内容 |
|--------|----------|
| 第3个月 | 中期评审（进度、是否继续） |
| 第6个月 | 结项评审（是否达标、是否成为导师候选人） |

### 4.3 沟通机制

- 最低频率：每两周至少1次正式沟通

### 4.4 退出机制

- **提前结项**：学员提前达标可提前结项
- **中期退出**：中期评审不达标可退出

---

## 五、结项评审标准

### 5.1 评审维度

| 维度 | 权重 | 评审内容 |
|------|------|----------|
| 代码贡献 | 40% | PR数量、代码质量、合并情况 |
| 社区参与 | 30% | Issue参与、Code Review、社区会议参与 |
| 技术成长 | 20% | 技术栈掌握程度、独立解决问题能力 |
| 文档产出 | 10% | 技术文档、知识分享 |

### 5.2 结项标准

- **通过**：各维度得分 ≥ 60分，且至少有 1 个 merged PR
- **优秀**：各维度得分 ≥ 80分，且有 ≥ 2 个 merged PR，可作为导师候选人

### 5.3 评审流程

1. 学员提交结项材料（PR/MR链接、贡献记录、总结报告）
2. 导师填写评审意见
3. 评审委员会审核确认
4. 公布评审结果

## 六、导师与学员职责

### 6.1 导师职责

| 职责类型 | 具体内容 |
|----------|----------|
| 技术指导 | 解答技术问题、协助理解代码架构、Review代码 |
| 流程指导 | 指导PR规范、社区沟通方式、贡献流程 |
| 进度跟踪 | 定期沟通、记录学员进度、及时上报问题 |
| 评审参与 | 参与中期评审、结项评审、提供评审意见 |

### 6.2 学员职责

| 职责类型 | 具体内容 |
|----------|----------|
| 学习实践 | 按计划完成学习任务、积极提交PR |
| 主动沟通 | 主动向导师汇报进度、提出问题 |
| 社区参与 | 参与社区讨论、遵守社区规范 |
| 文档记录 | 记录学习过程、撰写结项报告 |

---

## 七、组织管理与支持

### 7.1 组织角色

| 角色 | 职责 |
|------|------|
| 管理委员会 | 制定政策、认证导师、评审决策、资源协调 |
| 项目协调人 | 学员筛选、导师匹配、进度跟踪、问题协调 |

### 7.2 支持机制

| 支持类型 | 具体内容 |
|----------|----------|
| 培训支持 | 导师培训（指导技巧）、学员培训（开源流程） |
| 工具支持 | 沟通平台、进度跟踪工具、贡献记录系统 |
| 时间支持 | 导师指导时间计入工作量、学员有固定学习时间 |
